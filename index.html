Orbit: Android TV launcher design

The working design. Three rejected directions are in alternatives.html. Sections are numbered 4 to 9, continuing from the rejected directions.

4. Orbit (rounded tiles)

The chosen design. Full-bleed artwork of the last played item, title and synopsis in the top third, a translucent notice strip directly above the apps, then rounded app tiles carrying each app's own banner, then an inputs row styled after the TV's native input picker: a distinct colour marks the current input, and All inputs opens the TV's own picker. Details on the notice deep-links to the settings screen that fixes it; Dismiss hides it until the condition recurs.

5. Orbit Live (same layout, TiViMate hero)

What design 4 degrades to on live TV. TiViMate exposes no now-playing API, so the hero is built from the EPG: channel chip plus LIVE badge, programme title, EPG synopsis, the slot time with elapsed progress and a next-up line. Most channels have no artwork, so the backdrop falls back to a tint from the channel logo. Everything below the hero is identical to design 4.

6. Leaving favourites on uninstall

The uninstall feedback. The launcher listens for package removal, drops the app from the favourites row on its own and collapses the gap, so no dead tile is ever left behind. A confirmation sits top right for a few seconds and then fades. Shown mid-animation: Kodi has just finished uninstalling.

7. EPG fallback ladder

What the live hero shows as guide data thins out. The rule: never invent a bar. Progress is only drawn when a real start and stop time exist, so a missing guide looks missing rather than broken, and the tile still launches in every tier.

8. Scale, safe area and asset sizes

The mockups above are 1280px wide and the TV lays out in 960dp, so every number here is mockup px multiplied by 0.75. Android TV reports the same 960 x 540dp whether the panel renders at 1080p or 2160p, so the layout is written once in dp and the 4K panel just gets more pixels per dp. Confirm the real values on the set with adb shell wm size and adb shell wm density before trusting this table.

Layout

Screen 960 x 540dp. Safe area inset 48dp horizontal, 27dp vertical, which is the 64px padding in the mockups.

App tile 111 x 66dp, gap 12dp. Seven tiles plus gaps = 849dp, inside the 864dp of usable width.

Input tile 110 x 66dp, gap 9dp; Play Store and Settings 75 x 66dp.

Focus ring 3dp. Thinner disappears at couch distance.

RULEnever a px dimension in a layout file, and no hardcoded 1920

Type

Nothing below 12sp, which is 16px at mockup scale. Several labels in the earlier revisions sat at 8 to 10sp and have been raised.

Hero title 39sp, synopsis 14sp, meta and section labels 12sp, tile labels 12sp.

Use sp for text, dp for everything else, and test with the TV's own font size setting turned up.

RULEif it only reads on the Mac, it does not read from the couch

Assets

Tile artwork is read from the installed app at runtime, so the TV shows each app's own official logo. The launcher ships none.

Vector and adaptive icons render crisp at any size. Where an app only provides its 320 x 180 banner, sharpness depends on panel density: a downscale at 2x, about 1.4x upscale at 4x.

The logos in these mockups are placeholders; a browser cannot call PackageManager.

RULEvector first, bitmap second, never a shipped copy of someone's logo

9. Add to favourites

What the + tile at the end of the apps row opens. The row itself holds only the favourites, in your order, then + last, like the TV's own Favourite apps row; with none chosen it holds only the +. Adding from here is the same action as the long-press menu, just reachable without hunting for the app in the row.
